# SUMMERAWARDS 2027

Учебный командный сайт летней музыкальной премии SUMMERAWARDS

**Репозиторий:** https://github.com/uliana308/summer-awards

> Впервые здесь? Прочитайте разделы «Перед началом», «Первый запуск» и «Работа над своей страницей», а потом делайте по шагам.

## Стек

HTML, CSS, ванильный JavaScript. Без библиотек и сборщиков. Код страниц генерируется с помощью нейросети (DeepSeek / Qwen / ГигаЧат).

## Структура

```
index.html          главная
schedule.html       расписание концерта
tickets.html        схема зала и покупка билетов
lightstick.html     подключение лайтстика
css/common.css      ОБЩИЕ стили: цвета, шрифты, кнопки, боковая панель, меню, подвал
css/<страница>.css  стили своей страницы
js/common.js        ОБЩИЙ скрипт: данные, заказы, панель, меню, подвал, анимации
js/<страница>.js    скрипт своей страницы
assets/img/         картинки (фото групп: assets/img/artists/<id>.jpg)
```

Общие файлы `common.css` и `common.js` меняем только по договорённости с командой. Свою страницу пишем в своих `css/<страница>.css` и `js/<страница>.js`.

## Общие договорённости

**ID объектов** (в `js/common.js`, не переименовывать):

- Артисты: `art-bts`, `art-seventeen`, `art-skz`, `art-blackpink`, `art-twice`, `art-aespa`, `art-newjeans`, `art-enhypen`
- Дни: `day-1` (Sunset Stage, 14.08), `day-2` (Night Stage, 15.08)
- Зоны зала: `zone-fan`, `zone-vip`, `zone-a`, `zone-b`, `zone-c`
- Номинации: `nom-artist`, `nom-song`, `nom-album`, `nom-stage`, `nom-global`, `nom-dance`, `nom-ost`, `nom-fan`
- Место: `<зона>-r<ряд>-s<место>`, например `zone-b-r4-s12`

**Ключ хранения заказов:** `summerawards_orders` (localStorage). Формат заказа:

```json
{
  "id": "ord-1723650000000",
  "day": "day-2",
  "seats": [{ "seatId": "zone-b-r4-s12", "zoneId": "zone-b", "price": 6500 }],
  "total": 6500,
  "name": "Иван",
  "email": "ivan@mail.ru",
  "status": "active",
  "createdAt": "2027-08-01T12:00:00.000Z"
}
```

Отмена меняет `status` на `"cancelled"`, заказ не удаляется. Работаем с заказами только через функции из `common.js`:

- `getOrders()` — все заказы
- `getActiveOrders()` — только активные
- `addOrder({ day, seats, name, email })` — создать заказ, сумма считается сама
- `cancelOrder(id)` — отменить заказ
- `getTakenSeats(dayId)` — занятые места на день

Также доступны: `ARTISTS`, `DAYS`, `ZONES`, `NOMINATIONS`, `getArtist(id)`, `getZone(id)`, `getDay(id)`, `formatPrice(n)`, `showToast(text)`.

**Фото групп:** у каждого артиста в `ARTISTS` есть поле `photo` (например `assets/img/artists/art-bts.jpg`). Используйте его, а не свои копии картинок. Откуда взяты фото, написано в `assets/img/artists/README.txt`.

**Готовые атрибуты в HTML:**

- `data-reveal`: элемент плавно появляется при прокрутке.
- `data-scramble`: текст «расшифровывается» при появлении.
- `data-cursor="ТЕКСТ"`: при наведении курсор показывает подпись.
- `data-cursor-off`: курсор при наведении не меняется (так сделано на кнопках «Купить билет»).

**Стиль (важно, чтобы страницы выглядели одинаково):**

- Фон чёрный, акцент розовый `var(--c-pink)`, второй акцент пурпурный `var(--c-purple)`. Цвета берём только из переменных в `common.css`.
- Никаких скруглений: карточки и кнопки прямоугольные.
- Подписи без подчёркивания «_» на конце.
- Кнопки: `btn` (с рамкой), `btn--solid` (белая), `btn--pink` (розовая), `btn--sm` (маленькая). Подписи: `label`, `label--pink`. Заголовки: `h2`, `h3`.
- Мобильная версия обязательна. Проверяйте страницу на ширине 390 px (в браузере: F12 → значок телефона). Стили для телефона пишем в `@media (max-width: 900px) { … }`.

## Перед началом (один раз)

1. Зарегистрируйтесь на [github.com](https://github.com) и сообщите свой логин лиду.
2. Примите приглашение в репозиторий. Оно придёт на почту, или откройте https://github.com/notifications. Без этого не получится отправить свою ветку.
3. Установите:
   - [Git](https://git-scm.com/downloads) (все настройки по умолчанию);
   - [VS Code](https://code.visualstudio.com) и в нём расширение **Live Server**.
4. Представьтесь Git (имя и почта будут видны в коммитах):
   ```bash
   git config --global user.name "Имя Фамилия"
   git config --global user.email "почта@от.github"
   ```

## Первый запуск

1. Скачайте проект. В терминале VS Code (меню **Terminal → New Terminal**):
   ```bash
   git clone https://github.com/uliana308/summer-awards.git
   cd summer-awards
   ```
   При первом `push` Git откроет окно входа в GitHub: войдите в свой аккаунт.
2. Откройте папку в VS Code: **File → Open Folder → summer-awards**.
3. Нажмите правой кнопкой на `index.html` → **Open with Live Server**. Сайт откроется в браузере и будет обновляться сам после сохранения файла. Просто открывать файл двойным кликом хуже: заказы и переходы между страницами могут работать некорректно.

## Работа над своей страницей

**1. Создайте свою ветку** (один раз):
```bash
git checkout main
git pull
git checkout -b feature/schedule      # у каждого своя: feature/schedule, feature/lightstick, feature/tickets
```
Проверить, в какой ветке вы сейчас: `git branch` (текущая отмечена `*`).

**2. Делайте страницу.** В `<страница>.html` замените блок `<section class="stub">…</section>` своей вёрсткой. Не удаляйте `sa-rail`, `sa-menu`, `sa-topbar`, `sa-footer` и подключение `common.css` / `common.js`: из них собираются общие меню, шапка и подвал.

**3. Сохраняйте прогресс коммитами.** Каждый раз, когда кусок готов и работает:
```bash
git status                            # что изменилось
git add .
git commit -m "Расписание: таблица выступлений по дням"
```
Пишите в сообщении, что именно сделано. «fix» или «правки» не годится. Нужно минимум два осмысленных коммита: рабочая основа и доработка или исправление.

**4. Отправьте ветку на GitHub:**
```bash
git push -u origin feature/schedule   # первый раз
git push                              # следующие разы
```

**5. Создайте Pull Request (запрос на слияние).** На странице репозитория появится жёлтая плашка **Compare & pull request**: нажмите её. Если плашки нет: **Pull requests → New pull request**, где base: `main`, compare: ваша ветка.
- В названии укажите страницу, в описании — что сделано и что проверено.
- Справа в **Reviewers** выберите товарища, который будет проверять.

**6. Проверка.** Проверяющий открывает вкладку **Files changed**, запускает страницу у себя и пишет комментарии или нажимает **Review changes → Approve**. Чтобы запустить чужую ветку у себя:
```bash
git fetch
git checkout feature/lightstick
```
Автор исправляет замечания в той же ветке и снова делает `commit` и `push`. Pull Request обновится сам.

**7. Слияние.** Лид нажимает **Merge pull request**. После этого все обновляют у себя `main` (см. ниже).

## Как подтянуть свежие изменения из main

Если лид поменял общие файлы или кто-то уже слил свою страницу:
```bash
git add .
git commit -m "..."      # сначала сохраните свою работу
git checkout main
git pull
git checkout feature/schedule
git merge main
```
Если Git пишет **CONFLICT**, значит один и тот же кусок файла поменяли двое. VS Code подсветит конфликт: выберите **Accept Current / Accept Incoming / Accept Both**, сохраните файл, затем выполните `git add .` и `git commit`. Если не уверены, что выбрать, напишите лиду и ничего не удаляйте.

## Нельзя

- Пушить напрямую в `main`. Только через свою ветку и Pull Request.
- Менять `css/common.css`, `js/common.js` и чужие страницы. Если нужно что-то общее (новый цвет, функция, поле в `ARTISTS`), напишите лиду.
- Переименовывать ID артистов, дней, зон и номинаций, а также ключ `summerawards_orders`.
- Класть в репозиторий большие файлы (видео, исходники, фото больше 1 МБ). Картинки сжимайте до ширины ~1000 px.

## Частые проблемы

| Проблема | Что делать |
|---|---|
| `Permission denied` / `403` при push | Не принято приглашение в репозиторий или вход выполнен не в тот аккаунт |
| `rejected … fetch first` при push | В ветке на GitHub есть новые коммиты: `git pull`, затем снова `git push` |
| Случайно работала в `main` | Ещё не коммитили: `git checkout -b feature/<страница>`, и изменения переедут в новую ветку |
| Меню, шапка и подвал не появились | Проверьте, что подключены `css/common.css` и `js/common.js`, причём `common.js` стоит **до** своего скрипта |
| Стили не обновились | Ctrl + F5 (обновление без кэша) |
